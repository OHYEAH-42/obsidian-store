## 一、[[正则表达式]](Regular Expression)：


### 作用：
正则表达式主要用于处理字符串，最常见的三个场景是：

匹配（Validation）： 检查一段文本是否符合规则（例如：检查用户输入的手机号是不是 11 位数字）。

提取（Extraction）： 从大段文字中找出你想要的信息（例如：从网页代码中提取出所有的图片链接）。

替换（Replacement）： 把文本中符合某种模式的部分换成别的（例如：把所有的空格换成下划线）。 
### 语法：

量词的语法：

？：表示匹配前面字符0次或者1次（可选）
 例如： apple？  会匹配 appl 或者 apple
 
\*: 表示匹配前面的字符0次或者多次（可选）
  例如： ab*c    会匹配 ac 或者 abc 或者 abbbbbbbbbbbbbc 

 \+ : 表示匹配前面的字符一次及以上
  例如：  ab+c  会匹配  abc 或者 abbbbc

 {n}: 表示匹配前面的字符正好n次
 例如： ab{6}c   会匹配 abbbbbbc

 {n，}： 表示匹配至少n次

 {n，m}： 表示匹配从n到m次


分组与选择:

()：表示匹配（）内的位一个整体，比如  a（bc）{3}会匹配 abcbcbc

 | ： 表示或，比如  cat|dog 会匹配 cat 或者 doh 

\\: 表示转义符，比如要搜索？ 就要写成、？

基础字符匹配：

\. : 点号会匹配除了换行符以外的所有字符

\d: 匹配一个数字，及等价于\[0-9]

\D: 匹配一个非数字

\w: 匹配字母，数字或者下划线（单词字符）\W:匹配一个非单词字符

\s : 匹配任意空白符（空格，制表符等等）
\S : 匹配一个非空吧kk
\[abc]: 字符匹配，匹配括号内的任意一个字符
      例如：\[a-zA-Z]  表示匹配所有26位字母且大小写

\[^abc]: 表示非，这里表示匹配除了abc以外的任意字符

\^: 只会匹配行首
    例如 \^a  会匹配行首的a

\$: 只会匹配行尾
	例如\$a  会匹配行尾的a



## 二、[[有限自动机]](DFA/NFA)


### 定义：

有限自动机是一个抽象的数学模型，用于识别这一组字符串。
一个完整的FA包含五个要素：
- **$S$ (States)**：有限的状态集合。
    
- **$\Sigma$ (Alphabet)**：输入字符的集合（字母表）。
    
- **$s_0$**：唯一的初始状态。
    
- **$F$ (Final/Accepting States)**：接收状态集合（双圈表示）。
    
- **$\delta(s, c)$**：转移函数（在状态 $s$ 看到字符 $c$ 后跳转到哪个新状态）。

自动机的结构可以形式化地看作是一张有向图，称之为**状态图**
举个例子，完成「判断一个二进制数是不是偶数」的自动机如下：
![[Pasted image 20260414225024.png]]

NFA vs DFA

| 特性            | NFA(非确定性有限自动机)   | DFA(确定性有限自动机) |
| ------------- | ---------------- | ------------- |
| 转移唯一性         | 同一个字符可能有多个去向     | 同一个字符有且只有一个去向 |
| $\epsilon$ 转移 | 支持(不需要读字符也能跳转)   | 不支持           |
| 直观程度          | 更接近正则表达式，容易构造    | 复杂，难以手画       |
| 运行效率          | 曼                | 快             |
| 关系            | 每一个NFA都有一个等价的DFA | DFA是NFA的特殊形式  |

化简方法：我们先将状态分为两组，非终态组G1和终态组G2，当两个状态的相同输入，跳转到相同组别时，则这两个状态可以化简为同一个状态

ABC输入0都到G1组（G1->G1）
AB输入0到G1组(G1->G1)

## [[上下文无关文法]]

### 定义

一个上下文无关文法由四个部分组成，记作 G=(V,T,P,S)G=(V,T,P,S)：

- **V**：非终结符集合（variable / non-terminal），表示语法成分，如 `<表达式>`、`<语句>`，能再分解。
    
- **T**：终结符集合（terminal），即词法分析器产生的 Token，如 `+`、`if`、`id`、`number`，不能再分解
    
- **P**：产生式规则集合（production rules），形式为 A→α，其中A∈V，α 是由终结符和非终结符组成的字符串（可为空）。
    
- **S**：起始符号（start symbol），S∈V，代表整个语言的最顶层结构。

## 歧义

上述的例子实际上可以产生两种分析树
![[Pasted image 20260519215334.png]]

如果一个语法对于某个句子存在多于一个的分析树，那么这个语法就是二义性的。
换一种说法，有的语句存在不止一种的最左和最右推导。

或者另外一种歧义：

stmt → if expr then stmt
     | if expr then stmt else stmt
     | other

对于输入 `if e1 then if e2 then s1 else s2`，可以有两种解释：

- 内层 `if` 匹配 `else`：`if e1 then ( if e2 then s1 else s2 )`
    
- 外层 `if` 匹配 `else`：`if e1 then ( if e2 then s1 ) else s2`
    

这是编程语言文法中著名的歧义来源。

### 如何判断文法是否歧义

- **不可判定**：一般来说，判断一个任意的上下文无关文法是否歧义是 **不可判定问题**（形式上，歧义性问题在递归可枚举意义下是不可判定的）。****


### 歧义的处理

大多数编程语言要求 **无歧义文法**，常见的处理方式有：

| 方法              | 说明                                                                               |
| --------------- | -------------------------------------------------------------------------------- |
| **改写文法**        | 引入更多非终结符，显式规定优先级和结合性。例如改写 E → E + T \| T，T → T * F \| F，F → id，消除了 id+id*id 的歧义。 |
| **添加优先级/结合性声明** | 在解析器生成工具（Yacc、ANTLR）中，通过 `%left`、`%right` 等指令指定运算符优先级，告知解析器在冲突时选择哪个归约/移进。        |
| **使用无歧义解析算法**   | 某些解析算法（如 LR 族）虽然不能消除所有歧义，但可以通过冲突解决规则选择一个特定的语法树。                                  |

大多数都使用改写语法的方法来消除歧义。
而if-else那一种则是优先级

## 错误处理

编译器有两项任务，一是翻译有效的程序，生成该程序的正确代码，二是检测无效程序。 

### 三种不同的错误处理模式：

#### 恐慌模式（panic mode）

思路：发现错误时，语法分析器丢弃当前输入符号（或跳过一些符号），直到遇到一个预定义的**同步标记**（synchronizing token），例如分号 `;`、右括号 `)`、`end` 等。
优点：简单、容易实现、不会陷入无限循环。
缺点：可能会跳过合法代码，导致漏报错误。
应用：多数教材和简单编译器采用此方法。

例如：
（1++2）+3
第二个加号是错误的，在恐慌模式中，编译器会跳过这个加号，从2处开始，1+2得以识别
#### 错误产生式（error productions）

思路：在文法中预先增加**专门处理常见错误的产生式**，例如 `stmt → error ;` 或 `if error then stmt`。当分析器遇到错误时，按这些产生式规约，从而恢复并继续。
优点：可以针对常见错误给出更友好的提示（如“缺少右括号”）。
缺点：需要人工设计错误产生式，文法变得臃肿。

例如5x在编译器识别为错误的，但我们可以在文法中预先加入5x->5\*x，这样编译器就能识别5x了
#### 全局纠正（global correction）

这个用得少，不介绍了。

#### 左递归问题

一条产生式规则中，非终结符直接或间接出现在自身推导的最左边。例如：

- **直接左递归**：`A → A α | β`
    
- **间接左递归**：`A → B α, B → A β`

以不太显而易见的间接左递归为例子，会导致
A->Bα->Aβα->Bαβα->Aβαβα.......->Aβα......βα

这样子的无限循环

由于递归下降算法是从左到右解析的，所以无法处理左递归问题，这个时候就需要我们改变产生式了

比如上面的直接左递归`A → A α | β`，可以推导出：βα......α的形式
但自上而下递归方法是从左到右推导的，β无法出现在最左边，这个时候我们可以改写为右递归，这需要引入新的非终结符号

A'->αA‘|ε

### 移入—规约语法分析技术

自底向上分析（也称 **shift-reduce 分析**）使用一个**分析栈**和一个**输入缓冲区**。它的两个核心动作是：

1. [[移进]]（shift）
    
    - 从输入缓冲区取出下一个终结符，将其**压入栈顶**。
        
    - 相当于“读入”一个符号，等待后续与栈内其他符号一起归约为非终结符。
        
2. [[归约]]（reduce）
    
    - 当栈顶的若干符号与某条产生式的右部匹配时，将这些符号弹出，并将产生式的左部（非终结符）压入栈顶。
        
    - 相当于“识别”了一个语法结构。
        

**移入是自底向上分析的“前进”动作**，它不断把输入符号搬到栈里，直到栈顶能构成一个可归约的句柄。

如下例子
E->T | T+E
T->int | int\*T | (E)
![[Pasted image 20260521180147.png]]
将紫色竖线右边理解为栈，每次**移入**一个输入流中的token
直到栈中的字符串可以**归约**成一个非终结符(匹配了一条产生式)
重复以上操作

当解析器同时可以归约和移入时，存在移入-归约冲突
当解析器可以归约出两个非终结符时，即有两个产生式匹配了，存在归约-归约冲突


### [[句柄]]

如果某一个子串能够一步归约成某个非终结符，并且这一步正好是规范推导的逆过程，则这个字串称为这个句型的句柄。

比如前面图片的第二步，为什么int没有被归约成T。
这是因为int不是该句型的句柄，规范推导的过程中这一步不是T推导出int的


### [[可行前缀]]

在自底向上（LR）分析中，**可行前缀**是指：

- 能够出现在**分析栈**中的那些**右句型的前缀**，并且这个前缀可以延伸到某个**句柄**的右端（即尚未进行归约的部分）。
    
- 更正式地说：一个可行前缀是某个**最右句型**的前缀，且该前缀没有越过当前句柄的右边界。
    

例如，对于文法 `E → E + T | T`，输入 `int + int` 的分析过程中，栈里可能出现的符号串如 `E`、`E +`、`E + T` 等，它们都是可行前缀。

==**所有可行前缀组成的集合是一个正则语言**（由某个 DFA 接受）。==

### [[项目]]

一个 LR 项是一条产生式，并在其右部的某个位置加入一个 **圆点 `·`**，表示语法分析**当前已经分析到哪里**。

例如，对于产生式 `E → E + T`，可以有以下几种项：

- `E → · E + T` （还没开始分析右部）
    
- `E → E · + T` （已经分析了 `E`，期待 `+`）
    
- `E → E + · T` （已经分析了 `E` 和 `+`，期待 `T`）
    
- `E → E + T ·` （整个右部已分析完，可以归约）
    
在这种情况下，该产生式有4个项
这个 **点** 就像一个小光标，标记了栈顶与输入之间的边界。

其中，若产生式为A->ε，则只有一个项：A->.

# [[语义分析]]


词法分析，语法分析，语义分析构成了编译系统的前端，我们可以把这三者看作一个过滤器，到了最后，我们就能把不利于分析的字符串以及错误都过滤掉了。语义分析便是最后一道工序。

因此，语法分析需要进行多项检查，检查**含义**是否正确

因为编译器完成的分析是静态 (它在执 行之前发生)定义的，这样，语义分析也可称作静态语义分析 (static semantic analysis)。在一 个典型的静态类型的语言 (如C语言)中，语义分析包括构造符号表、记录声明中建立的名字的 含义、在表达式和语句中进行类型推断和类型检查以及在语言的类型规则作用域内判断它们 的正确性。

静态语义分析包括执行分析的*描述*和使用合适的算法对分析的*实现*。与语法分析类比，就是使用[[BNF和EBNF]]和[[上下文无关文法]]描述[[语法]]结构，又使用[[自顶向下的语法分析]]和[[自底向上的语法分析]]的算法来实现语法结构。
类似的，由于语义没法规范化表达，所以采用这样的方式：确定语言实体的[[属性]]或特性，它们必须进行计算并写成属性等式或语义规则，并描述这些属性的计算如何与语言的文法规则相关。这样的一组属性和等式称作[[属性文法]](attribute grammar)

- Recurse： 处理n的子节点（先左子树在右子树）
- after： 完成节点n的处理

## 类型理论

### [[类型推导规则]]

类型类型推导（Type Inference）的核心，就是让[[编译器]]帮你“猜”出变量或表达式的类型，让你在编写代码时，可以写出 `x = 5` 这样简洁的语句，而不必每次都繁琐地声明 `int x = 5`

### 类型环境

**在CS143中**，类型环境由以下三部分组成：

####  对象环境 `O`（Object Environment）

**作用**：跟踪当前作用域内**程序变量**（包括普通变量、`let` 绑定变量、`case` 分支变量）的类型。

**内容**：一个从变量名到类型的**有限映射**，例如：

text

O = { x: Int, y: Bool, self: SELF_TYPE }

**特点**：

- **动态变化**：进入新的作用域（如 `let` 表达式、`case` 分支、方法体）时，`O` 会扩展或收缩。
    
- **局部性**：只关心当前可见的变量，不跨越函数边界。
    

**典型规则**（变量引用）：

text

O(x) = T
─────────
O ⊢ x : T

只要在 `O` 中查到变量 `x` 的类型，就可以使用。


#### 2. 方法环境 `M`（Method Environment）

**作用**：记录整个程序中**所有方法的签名**（参数类型和返回类型）。它相当于一个全局的方法符号表。

**内容**：一个从 **（类名, 方法名）** 到**函数类型**的映射。通常写作：

text

M(C, f) = (T₁, T₂, …, Tₙ) → T

表示类 `C` 中的方法 `f` 接受 `n` 个参数（类型分别为 `T₁ … Tₙ`），并返回类型 `T`。

**特点**：

- **全局不变**：在整个类型检查过程中，`M` 是只读的，在分析完所有类的声明后建立。
    
- **支持继承**：如果当前类没有定义某个方法，可能需要到父类中查找（但 `M` 通常已经包含了所有可见的方法，或者检查器会沿着继承链查询）。
    

**典型规则**（方法调用）：

text

O, M, C ⊢ e₀ : T₀      M(T₀, f) = (T₁', …, Tₙ') → T'      O, M, C ⊢ eᵢ : Tᵢ      Tᵢ <: Tᵢ'
─────────────────────────────────────────────────────────────
                     O, M, C ⊢ e₀.f(e₁, …, eₙ) : T'

前提中：

- 先求出 `e₀` 的类型 `T₀`；
    
- 从 `M` 中找到 `T₀` 类的方法 `f` 的签名；
    
- 检查实参类型是否与参数类型兼容（子类型关系）；
    
- 最后整个调用的类型就是返回类型 `T'`。
    


#### 3. 当前类 `C`（Current Class）

**作用**：记录类型检查器**当前正在处理哪个类**。这对于处理 `SELF_TYPE` 以及访问当前类的属性/方法至关重要。

**内容**：一个类名，例如 `C = A` 表示正在检查类 `A` 的某个方法体或初始化表达式。

**特点**：

- **单一值**：在任意时刻，`C` 就是一个类名（或者特殊标记，如“不在任何类中”）。
    
- **用于 `self` 和 `SELF_TYPE`**：`self` 的类型就是 `SELF_TYPE`，而 `SELF_TYPE` 在类型检查时会被解析为**当前类**（以及可能被继承后的具体类）。例如在类 `A` 中，`SELF_TYPE` 就是 `A`；如果在子类 `B` 中调用了继承自 `A` 的方法，该方法体内的 `self` 类型实际上是 `B`，这需要通过 `C` 来体现。
    

**典型规则**（`self` 变量）：

text

C 是当前类
───────────
O, M, C ⊢ self : SELF_TYPE

而在检查继承或方法覆盖时，`C` 也会用于判断某个方法是否合法（例如返回类型是否为子类型）。



#### 三者如何协同工作？

类型规则的标准形式是：

O, M, C ⊢ e : T

意思是：在对象环境 `O`、全局方法环境 `M`、当前类 `C` 的上下文中，表达式 `e` 的类型是 `T`。

- **`O`** 负责局部变量和参数；
    
- **`M`** 负责跨类的方法查找；
    
- **`C`** 负责处理与当前类相关的类型（特别是 `SELF_TYPE` 和继承）。
    

**例子**：检查 `self.f(3)` 这个表达式。

1. 从 `C` 得知当前类是 `A`。
    
2. 从 `O` 中查到 `self` 的类型是 `SELF_TYPE`（可以视为当前类的实例）。
    
3. 从 `M` 中查找 `M(A, f)` 得到 `(Int) → Bool`。
    
4. 检查参数 `3` 的类型 `Int` 是否兼容 `Int`（是）。
    
5. 结论：整个表达式类型为 `Bool`。
### [[子类型]]

**子类型**：`S <: T`(或者≤) 表示 `S` 是 `T` 的子类型。
**超类型**：`T` 是 `S` 的超类型。
**关键性质**：任何对 `T` 类型值的操作，也能同样作用于 `S` 类型的值（且行为符合预期）。


### 类型检查
