# 数据库规范化理论（范式理论）

## 一、基本概念

### 1. 函数依赖（Functional Dependency）

**定义**：设 R(U) 是属性集 U 上的关系模式，X、Y ⊆ U。若对于 R 的任意两个元组 t1、t2，只要 t1\[X\] = t2\[X\]，就有 t1\[Y\] = t2\[Y\]，则称 **X 函数决定 Y**，记作 **X→Y**，称 X 为 **决定因素**。

**分类**：
| 类型 | 定义 | 示例 |
|------|------|------|
| **平凡函数依赖** | Y ⊆ X，则 X→Y 必然成立 | A→A, AB→A |
| **非平凡函数依赖** | Y ⊈ X 且 Y ≠ ∅ | A→B |
| **完全函数依赖** | X→Y 且对 X 的真子集 X' 都有 X'—/\→Y | (学号,课程号)→成绩（完全） |
| **部分函数依赖** | X→Y 且存在 X' ⊂ X 使 X'→Y | (学号,课程号)→姓名（部分，因为学号→姓名） |
| **传递函数依赖** | X→Y, Y→Z, 且 Y—/\→X | 学号→系号, 系号→系主任 ⇒ 学号⇢系主任 |

> **记号**：X→Y 是 FD（函数依赖），X⇢Y 是传递依赖

### 2. Armstrong 公理系统

| 公理 | 规则 |
|------|------|
| **自反律** | 若 Y ⊆ X，则 X→Y |
| **增广律** | 若 X→Y，则 XZ→YZ |
| **传递律** | 若 X→Y 且 Y→Z，则 X→Z |

**推论**：
| 推论 | 规则 |
|------|------|
| **合并律** | X→Y 且 X→Z ⇒ X→YZ |
| **分解律** | X→YZ ⇒ X→Y 且 X→Z |
| **伪传递律** | X→Y 且 YZ→W ⇒ XZ→W |

### 3. 属性集闭包

**定义**：在 F 下，由 X 所能函数决定的所有属性的集合，记作 **X⁺**。

**算法**：
```
X⁺ = X
do {
    for each FD Y→Z in F:
        if Y ⊆ X⁺ then X⁺ = X⁺ ∪ Z
} while (X⁺ 有变化)
```

> **用途**：判断 X 是否为候选键（若 X⁺ = U，则 X 是超键）；判断 FD X→Y 是否成立（若 Y ⊆ X⁺，则成立）。

### 4. 最小函数依赖集（最小覆盖）

**步骤**：
1. **右部单一化**：将每个 FD X→YZ 拆分为 X→Y, X→Z
2. **左部最小化**：对每个 FD X→Y，检查 X 中是否有冗余属性
3. **去冗余**：删除可由剩余 FDs 推导出的 FD

## 二、候选键的求法

### 属性分类法

| 类别       | 定义                 |
| -------- | ------------------ |
| **L 类**  | 仅出现在 FD 左边，从未出现在右边 |
| **R 类**  | 仅出现在 FD 右边，从未出现在左边 |
| **LR 类** | 既出现在左边又出现在右边       |
| **N 类**  | 左右均未出现             |

**求候选键口诀**：
1. **L 类必为候选键成员**（L 类属性必须在每个候选键中）
2. **R 类必不为候选键成员**
3. **N 类必为候选键成员**（N 类属性必须在每个候选键中）
4. **LR 类逐个尝试**：将 L 类 + N 类设为 X，若 X⁺ = U，则 X 是候选键；否则向 X 中添加 LR 类属性再测试

### 判定候选键的通用方法

1. 找出 **L 类** 和 **N 类** 属性 → 必在候选键中
2. 设 X = L ∪ N，求 X⁺：
   - 若 X⁺ = U，则 X 是唯一候选键
   - 否则，依次尝试向 X 中加入 LR 类属性，求闭包看能否达到 U
3. 对找到的每个候选键，检查其最小性（真子集是否也是超键）

## 三、范式及其判定

### 范式的层次关系

```
1NF ⊃ 2NF ⊃ 3NF ⊃ BCNF
```

### 各范式定义

| 范式       | 条件                           | 通俗理解              |
| -------- | ---------------------------- | ----------------- |
| **1NF**  | 所有属性都是**不可分的基本数据项**          | 无表中有表，无多值属性       |
| **2NF**  | 1NF + **每个非主属性完全函数依赖于每个候选键** | 消除**部分依赖**        |
| **3NF**  | 2NF + **每个非主属性不传递依赖于任何候选键**  | 消除**传递依赖**        |
| **BCNF** | 3NF + **每个决定因素（FD 左部）都是超键**  | 消除**主属性对非主属性的依赖** |
|          |                              |                   |

> **注意**：若所有属性都是**主属性**（即都在候选键中），则关系一定满足 3NF（无非主属性）。

### BCNF 的等价定义

- R 中每一个非平凡 FD X→Y，X 都是超键
- 即 每个 FD 的左边都必须包含候选键

### 为什么 BCNF 比 3NF 更严格？

- 3NF 允许：非主属性不传递依赖即可，允许主属性部分依赖
- BCNF 禁止：任何属性（包括主属性）对非超键的依赖

## 四、模式分解

### 1. 无损连接分解

**定义**：分解后的关系通过自然连接能恢复为原关系，无数据丢失。

**判定方法 — 追踪法（Chase 算法）**：
1. 构造初始表格：行为分解的关系 Ri，列为属性 Aj
2. 若 Aj ∈ Ri，填 aⱼ；否则填 bᵢⱼ
3. 对每个 FD X→Y，找出 X 值相同的行，将 Y 值统一（有 a 则填 a）
4. 若某行全为 a，则是无损连接分解

> **特殊判定**：将关系 R 分解为 R₁ 和 R₂，若 **R₁ ∩ R₂ → R₁** 或 **R₁ ∩ R₂ → R₂**，则为无损连接分解（即 **公共属性是某个关系的键**）。

### 2. 保持函数依赖的分解

**定义**：分解后所有 FD 仍能被保持（可在分解后的单个关系上验证）。

**判定**：设 G = ∪ πᵣᵢ(F)（各关系上 F 投影的并集），若 G⁺ = F⁺，则保持函数依赖。

### 3. BCNF 分解算法（保证无损连接）

```
while (存在 Ri 不是 BCNF) {
    找到 Ri 中违反 BCNF 的 FD X→Y
    将 Ri 分解为：
        R₁ = X⁺          // X 的闭包
        R₂ = X ∪ (Ri - X⁺) // X 加上 Ri 中不在 X⁺ 里的属性
}
```

**性质**：保证无损连接，但不一定保持函数依赖。

### 4. 3NF 合成算法（保证保持函数依赖）

```
1. 求 F 的最小覆盖 Fm
2. for each FD X→Y in Fm:
       创建关系模式 (X ∪ Y)
3. if (没有任何关系包含候选键)
       额外创建一个包含候选键的关系
4. 合并可合并的关系（子集关系）
```

**性质**：保证保持函数依赖，且一定达到 3NF，但不一定无损连接（可以额外加候选键表来保证）。

## 五、典型例题详解

### 例题 1

> 给定关系模式 R<U, F>，U = {A, B, C, D, E}，F = {A→BC, CD→E, B→D, E→A}
>
> 求 R 的候选码，判断范式级别，将 R 分解成 BCNF（保证无损连接），判断是否保持函数依赖。

#### 步骤①：求候选键

**属性分类**：
- L 类：无
- R 类：无
- LR 类：A, B, C, D, E（全部）
- N 类：无

逐一计算各属性及属性组合的闭包：

| 属性/组合 | 闭包推理过程 | 结果 |
|-----------|-------------|------|
| **A** | A→BC ⇒ {A,B,C}；B→D ⇒ {A,B,C,D}；CD→E ⇒ {A,B,C,D,E} | A⁺ = **U** ✓ |
| **E** | E→A ⇒ {E,A}；A→BC ⇒ {A,B,C,E}；B→D ⇒ {A,B,C,D,E} | E⁺ = **U** ✓ |
| **B** | B→D ⇒ {B,D} | B⁺ = {B,D} ✗ |
| **C** | 无左部为 C 的 FD | C⁺ = {C} ✗ |
| **D** | 无左部为 D 的 FD | D⁺ = {D} ✗ |
| **BC** | B→D ⇒ {B,C,D}；CD→E ⇒ {B,C,D,E}；E→A ⇒ **U** | BC⁺ = **U** ✓ |
| **CD** | CD→E ⇒ {C,D,E}；E→A ⇒ {A,C,D,E}；A→BC ⇒ **U** | CD⁺ = **U** ✓ |

**检查最小性**：
- BC：B⁺ ≠ U，C⁺ ≠ U ⇒ 最小 ✓
- CD：C⁺ ≠ U，D⁺ ≠ U ⇒ 最小 ✓

> **候选键：A、E、BC、CD**（共 4 个）

**主属性**：A, B, C, D, E（**所有属性都是主属性**）

#### 步骤②：判断最高范式

**1NF**：所有属性均为原子属性 ✓

**2NF**：所有属性都是主属性 ⇒ **无非主属性的部分依赖**，满足 2NF ✓

**3NF**：所有属性都是主属性 ⇒ **无非主属性的传递依赖**，满足 3NF ✓

**BCNF**：检查每个 FD 的左部是否为超键：
| FD | 左部是否为超键？ | 判定 |
|----|-----------------|------|
| A→BC | A 是候选键 ✓ | 通过 |
| CD→E | CD 是候选键 ✓ | 通过 |
| **B→D** | B⁺ = {B,D} ≠ U **✗** | **违反 BCNF** |
| E→A | E 是候选键 ✓ | 通过 |

> **最高范式：3NF**

#### 步骤③：分解到 BCNF（保证无损连接）

使用 BCNF 分解算法，选择违反 BCNF 的 FD **B→D** 进行分解：

**第 1 轮分解**（基于 B→D）：
- B⁺ = {B, D}
- R₁ = B⁺ = {B, D}
- R₂ = B ∪ (U − B⁺) = {B} ∪ {A, C, E} = {A, B, C, E}

此时 ρ = {R₁(B,D), R₂(A,B,C,E)}

**R₁(B,D)**：
- 投影 FD：B→D
- B 是 R₁ 的候选键，R₁ 满足 BCNF ✓

**R₂(A,B,C,E)**：
- 投影 FD：A→BC, E→A
- 候选键：E（E⁺ = {E,A,B,C} = R₂）
- **检查 BCNF**：A→BC，A 不是 R₂ 的超键（A⁺ = {A,B,C} ≠ R₂）⇒ **违反 BCNF**，需继续分解

**第 2 轮分解**（基于 A→BC，在 R₂ 中）：
- A⁺(在 R₂ 中) = {A, B, C}
- R₂₁ = A⁺ = {A, B, C}
- R₂₂ = A ∪ (R₂ − A⁺) = {A} ∪ {E} = {A, E}

**R₂₁(A,B,C)**：FD A→BC，A 是候选键 ✓ BCNF ✓
**R₂₂(A,E)**：FD E→A，E 是候选键 ✓ BCNF ✓

> **最终 BCNF 分解**：
> - **R₁(B, D)** — FD：B→D
> - **R₂₁(A, B, C)** — FD：A→BC
> - **R₂₂(A, E)** — FD：E→A

**无损连接性**：BCNF 分解算法保证无损连接 ✓

#### 步骤④：判断是否保持函数依赖

检查原 F = {A→BC, CD→E, B→D, E→A} 的每个 FD：

| FD | 是否保持？ | 说明 |
|----|-----------|------|
| A→BC | ✓ | 在 R₂₁(A,B,C) 中保持 |
| **CD→E** | **✗** | C 和 D 不在同一关系中，**丢失** |
| B→D | ✓ | 在 R₁(B,D) 中保持 |
| E→A | ✓ | 在 R₂₂(A,E) 中保持 |

> **结论：不保持函数依赖**，因为 CD→E 丢失。

### 例题 2

> 给定关系模式 R<U, F>，U = {A, B, C, D, E}，F = {AB→C, B→D, C→E, CE→B, AC→B}
>
> 求 R 的候选码，判断范式级别，将 R 分解成 3NF（保持函数依赖），判断是否有无损连接性。

#### 步骤①：求候选键

**属性分类**：
| 属性 | 出现在左边 | 出现在右边 | 类别 |
|------|-----------|-----------|------|
| **A** | AB→C, AC→B | 无 | **L 类** |
| B | AB→C, CE→B, AC→B | CE→B | LR 类 |
| C | AB→C, C→E, CE→B, AC→B | AB→C, AC→B | LR 类 |
| D | 无 | B→D | **R 类** |
| E | CE→B | C→E | LR 类 |

- L 类：**A** ⇒ A 必在候选键中
- R 类：**D** ⇒ D 不在候选键中
- LR 类：B, C, E

从 A 出发，计算闭包：

| 属性组合 | 闭包推理 | 结果 |
|---------|---------|------|
| A | 无左部为 A 的 FD | A⁺ = {A} ✗ |
| **AB** | AB→C ⇒ {A,B,C}；B→D ⇒ {A,B,C,D}；C→E ⇒ **U** | **AB⁺ = U** ✓ |
| **AC** | AC→B ⇒ {A,C,B}；B→D ⇒ {A,B,C,D}；C→E ⇒ **U** | **AC⁺ = U** ✓ |
| AE | 无左部含 AE 的 FD；E 单独无 FD；A 无 FD | AE⁺ = {A,E} ✗ |

**检查最小性**：
- AB：A⁺ ≠ U，B⁺ = {B,D} ≠ U ⇒ 最小 ✓
- AC：A⁺ ≠ U，C⁺ = {C,E} ≠ U ⇒ 最小 ✓

> **候选键：AB、AC**（共 2 个）

**主属性**：A, B, C
**非主属性**：D, E

#### 步骤②：判断最高范式

**1NF**：所有属性原子化 ✓

**2NF**：检查非主属性对候选键是否存在部分依赖：
- **D**：对候选键 AB，B→D ⇒ **D 部分依赖于 AB**（B ⊆ AB，且 B→D）⇒ **违反 2NF** ✗

> **最高范式：1NF**

#### 步骤③：分解到 3NF（保持函数依赖）

使用 **3NF 合成算法**：

**Step 1：求 F 的最小覆盖 Fm**

F = {AB→C, B→D, C→E, CE→B, AC→B}

① 右部单一化（已是单属性）：
F = {AB→C, B→D, C→E, CE→B, AC→B}

② 左部最小化（检查冗余属性）：
| FD | 检查过程 | 结果 |
|----|---------|------|
| AB→C | A 冗余？B⁺(在 F 中)={B,D} 不含 C。B 冗余？A⁺={A} 不含 C | 无冗余 |
| CE→B | C 冗余？E⁺={E} 不含 B。E 冗余？C⁺={C,E} 不含 B | 无冗余 |
| AC→B | A 冗余？C⁺={C,E} 不含 B。C 冗余？A⁺={A} 不含 B | 无冗余 |

③ 去冗余：
- **AC→B**：去掉 AC→B 后，AC⁺(在 F-{AC→B} 中) = {A,C} 经 C→E 得 {A,C,E}，经 CE→B 得 {A,B,C,E}，经 B→D 得 **U** ⇒ AC→B 可由其他推导 ⇒ **冗余，删除** ✓

> **Fm = {AB→C, B→D, C→E, CE→B}**

**Step 2：为每个 FD 创建关系**

| FD | 创建的关系 |
|----|-----------|
| AB→C | **R₁(A, B, C)** |
| B→D | **R₂(B, D)** |
| C→E | **R₃(C, E)** |
| CE→B | **R₄(C, E, B)** |

**Step 3：检查候选键**
候选键 AB 和 AC，AB ⊆ R₁(A,B,C) ⇒ **已包含候选键** ✓

**Step 4：合并子集关系**
R₃(C, E) ⊆ R₄(C, E, B) ⇒ **合并到 R₄，删除 R₃**

> **最终 3NF 分解**：
> - **R₁(A, B, C)** — FD：AB→C
> - **R₂(B, D)** — FD：B→D
> - **R₃(C, E, B)** — FD：C→E, CE→B
>
> 保持函数依赖 ✓

> **补充**：各子关系实际的最高范式
> - R₁(A,B,C)：AB→C, AC→B ⇒ 候选键 AB, AC ⇒ **BCNF**
> - R₂(B,D)：B→D ⇒ 候选键 B ⇒ **BCNF**
> - R₃(C,E,B)：C→E, CE→B ⇒ 候选键 C ⇒ **BCNF**
> 
> 可见该分解实际达到了 BCNF。

#### 步骤④：判断是否无损连接

用 **Chase 追踪法**：

**初始表格**：

| 关系 | A | B | C | D | E |
|------|---|---|---|---|---|
| **R₁**(A,B,C) | a₁ | a₂ | a₃ | b₁₄ | b₁₅ |
| **R₂**(B,D) | b₂₁ | a₂ | b₂₃ | a₄ | b₂₅ |
| **R₃**(C,E,B) | b₃₁ | a₂ | a₃ | b₃₄ | a₅ |

**应用 FDs**（使用 Fm = {AB→C, B→D, C→E, CE→B}）：

| FD | 匹配行 | 操作 | 更新后 |
|----|--------|------|--------|
| AB→C | 无两行 A 相等 | — | 不变 |
| **B→D** | 所有行 B=a₂ | 第二行有 a₄，统一 D | R₁.D=b₁₄→a₄，R₃.D=b₃₄→a₄ |
| **C→E** | R₁ 和 R₃ 的 C=a₃ | 第三行有 a₅，统一 E | R₁.E=b₁₅→a₅ |
| CE→B | 已有 C=a₃, E=a₅ 的行 | — | — |

**更新后的表格**：

| 关系 | A | B | C | D | E |
|------|---|---|---|---|---|
| **R₁** | **a₁** | a₂ | a₃ | **a₄** | **a₅** |
| R₂ | b₂₁ | a₂ | b₂₃ | a₄ | b₂₅ |
| R₃ | b₃₁ | a₂ | a₃ | a₄ | a₅ |

**R₁ 行全为 a** ⇒ **无损连接分解 ✓**

> **最终结论**：
> - 候选键：**AB、AC**
> - 最高范式：**1NF**
> - 3NF 分解结果：**R₁(A,B,C)、R₂(B,D)、R₃(C,E,B)**
> - 保持函数依赖：**✓ 是**
> - 无损连接：**✓ 是**

## 六、题型总结

| 问题 | 方法要点 |
|------|---------|
| **求候选键** | 属性分类法，求闭包，检查最小性 |
| **判断范式** | 1NF→2NF→3NF→BCNF 逐级检查，关注主/非主属性 |
| **分解到 3NF** | ①最小覆盖 ②按 FD 建表 ③包含候选键 ④合并子集 |
| **分解到 BCNF** | ①找违反 BCNF 的 FD ②X⁺ 和 X∪(U−X⁺) 分离 ③递归 |
| **无损连接判定** | ①两分解：公共属性→任一子集 ②多分解：Chase 追踪法 |
| **保持函数依赖** | 检查每个 FD 是否在某个子关系上成立，或可由投影 FDs 推导 |

### 重要结论

| 分解算法 | 无损连接 | 保持函数依赖 |
|---------|---------|------------|
| BCNF 分解算法 | 保证 | **不一定** |
| 3NF 合成算法 | **不一定**（可加候选键表保证） | 保证 |
