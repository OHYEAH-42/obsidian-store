# 核心思想

**避免重复计算**。将原问题分解为子问题，每个子问题只计算一次，保存结果（空间换时间），自底向上递推出原问题的解。

## 一个例子

![[Pasted image 20260624112540.png]]

观察可以得到，爬上第n阶的方案数量，等于n-1阶和n-2阶的方案数量之和。
$$
dp[n]=dp[n-1]+dp[n-2]
$$
其实就是斐波那契数列。

从地面触发，利用回溯来穷举所有可能性。
将爬楼梯想象为多轮选择的过程：
每一轮，选择上1阶或2阶，当到达所指定的阶级n，则记录一个方案
如果超过了阶级，则舍弃这一条剪枝

```
/* 回溯 */
void backtrack(vector<int> &choices, int state, int n, vector<int> &res) {
	// 当爬到第 n 阶时，方案数量加 1
	if (state == n)
		res[0]++;
	// 遍历所有选择
	for (auto &choice : choices) {
		// 剪枝：不允许越过第 n 阶
		if (state + choice > n)
		continue;
		// 尝试：做出选择，更新状态
		backtrack(choices, state + choice, n, res);
		// 回退
	}
}


/* 爬楼梯：回溯 */
int climbingStairsBacktrack(int n) {
	vector<int> choices = {1, 2}; // 可选择向上爬 1 阶或 2 阶
	int state = 0;                // 从第 0 阶开始爬
	vector<int> res = {0};        // 使用 res[0] 记录方案数量
	backtrack(choices, state, n, res);
	return res[0]
}
```


### 方法一：暴力搜索

```
/* 搜索 */
int dfs(int i) {
	// 已知 dp[1] 和 dp[2] ，返回之
	if (i == 1 || i == 2)
		return i;
	// dp[i] = dp[i-1] + dp[i-2]
	int count = dfs(i- 1) + dfs(i- 2);
	return count;
}

/* 爬楼梯：搜索 */
int climbingStairsDFS(int n) {
	return dfs(n);
}
```

其实就是一个自顶向下的递归，读一遍代码就明白了

但是这个方法会有一个缺点，计算$dp[9]=dp[8]+dp[7]$时，计算了一次$dp[7]和dp[8]$；
接着递归计算$dp[8]=dp[7]+dp[6]$时，会发现我们要重新计算dp\[7]，以此类推，会有越来越多的重复计算，导致该算法的时间复杂度为O(log 2^n)



### 方法二：记忆化搜索

在方法一的基础上记录dp\[i]的值，减少重复计算的步骤

```
/* 记忆化搜索 */
int dfs(int i, vector<int> &mem) {
	// 已知 dp[1] 和 dp[2] ，返回之
	if (i == 1 || i == 2)
		return i;
	// 若存在记录 dp[i] ，则直接返回之
	if (mem[i] !=-1)
		return mem[i];
	// dp[i] = dp[i-1] + dp[i-2]
	int count = dfs(i- 1, mem) + dfs(i- 2, mem);
	// 记录 dp[i]
	mem[i] = count;
	return count;
}

/* 爬楼梯：记忆化搜索 */
int climbingStairsDFSMem(int n) {
	// mem[i] 记录爬到第 i 阶的方案总数，-1 代表无记录
	vector<int> mem(n + 1,-1);
	return dfs(n, mem);
}

```

时间复杂度减少到O(n)


### 方法三：动态规划

前两种都是自顶向下的方法，将大问题递归减小到小问题，解决之后再逐层回溯收集解
而动态规划则一开始就从最小问题开始，迭代构建更大的子问题的解，直到得到原问题的解

```
/* 爬楼梯：动态规划 */
int climbingStairsDP(int n) {
	if (n == 1 || n == 2)
		return n;
	// 初始化 dp 表，用于存储子问题的解
	vector<int> dp(n + 1);
	// 初始状态：预设最小子问题的解
	dp[1] = 1;
	dp[2] = 2;
	// 状态转移：从较小子问题逐步求解较大子问题
	for( int i = 3; i <= n; i++ )
		dp[i] = dp[i-1] + dp[i-2];
	return dp[n];
}
```


根据以上内容，总结出动态规划常用术语：
- [[dp表]]：即数组dp，dp\[i]表示状态 i 对应的子问题的解
- 初始状态：最小子问题对应的状态（例题中就是第1阶和第2阶他台阶）
- [[状态转移方程]]：就是递推公式$dp[n]=dp[n-1]+dp[n-2]$



> [!NOTE] 空间优化 
> 由于dp\[i]只与dp\[i-1]和dp\[i-2]有关，我们可以用变量记录这两个数值，省去数组
> 空间复杂度从O(n)降低至O（1），这种空间优化技巧叫做[[滚动数组]]



# [[动态规划问题特性]]

## 最优子结构（最优性原理）

**含义**：原问题的最优解时从子问题的最优解构建得来的


## 重叠子问题

**含义**：在递归求解的过程中，子问题会被反复、重复地计算多次


## 无后效性

**含义**：给定一个确定的状态，它的未来发展只与当前状态有关，而与过去经历的所有状态无关。

## 问题判断

满足[[动态规划问题特性]]三个条件的，通常就适合用动态规划求解。但往往没那么容易看出来，此时我们观察问题是否可以使用回溯（穷举）解决。

如果问题包含明确的决策概念，并且解是通过一系列决策产生的，那么它就满足[[决策树模型]]，通常可以使用回溯解决。

在此基础上，判断还有一些加分项：
- 问题包含最值等最优化描述
- 问题的状态能使用一个列表、多维矩阵、或树来表示，并且一个状态与其周围的状态存在递推关系。

一些减分项：
- 问题的目标是找出所有可能的方案，而非最优解。
- 问题描述中有明显的排列组合的特征，需要返回具体的多个方案。

通过以上这些，就可以判断是否适用动态规划求解


## 问题求解步骤

通常遵循以下步骤：
- 描述决策
- 定义状态
- 建立dp表
- 推导状态转移方程
- 确定边界条件
