# 如何利用四种 LR 方法进行语法分析

---

## 核心结论

> **四种方法的分析过程（总控算法）完全一样，区别仅在于分析表不同。**

分析表决定了每个状态下做什么动作。构造分析表越精确（LR(1) > LALR(1) > SLR(1) > LR(0)），分析时冲突越少。

---

## LR 总控算法（四种方法通用）

```
输入：输入串 w，LR 分析表（Action + Goto）
输出：若 w 是句子则接受，否则报错

初始化：
    栈 = [$] + [状态0]
    ip  = 指向 w 的第一个符号

while (1) {
    令 s = 栈顶状态
    令 a = ip 所指的当前输入符号
    
    if (Action[s][a] == "sⱼ") {
        // 移进：将 a 和状态 j 依次压栈
        push(a); push(j);
        ip++;                    // 指针前进
    }
    else if (Action[s][a] == "rⱼ") {
        // 归约：用第 j 条产生式 A → β
        弹出 2 × |β| 个符号;     // |β| 个文法符号 + |β| 个状态
        令 t = 当前栈顶状态;
        将 A 压栈;
        将 Goto[t][A] 压栈;      // 查 Goto 表
        // （ip 不动！）
    }
    else if (Action[s][a] == "acc") {
        分析成功，接受;
        break;
    }
    else {
        ERROR();                  // 分析表中为空 → 语法错误
    }
}
```

---

## 示例文法

```
(0) E' → E
(1) E  → E + n
(2) E  → n
```

FOLLOW(E') = {\$}，FOLLOW(E) = {$, +}

LR(0) DFA：

```
I₀: E'→·E,  E→·E+n,  E→·n
I₁: E'→E·,  E→E·+n
I₂: E→n·
I₃: E→E+·n
I₄: E→E+n·
```

---

## 一、用 LR(0) 分析——分析 `n + n`

### LR(0) 分析表

```
     n    +    $    E
0    s2            1
1    s3/r2  s3   acc        ← 状态1：E'→E· 对所有符号归约
2    r2    r2   r2          ← 状态2：对所有符号 r2
3    s4
4    r1    r1   r1
```

这个文法恰好 LR(0) 没有实质冲突（E'→E· 对 $ 填 acc，其他情况有约定），但实际分析 `n+n` 没问题。

### 分析过程

```
步骤  栈              输入       动作
1     $0              n+n$       s2 → 移进 n，进入状态2
2     $0 n 2          +n$        r2 → 用 E→n 归约
                                 弹出 |n|=1 对 = 2个
      $0              +n$        t=0, Goto[0,E]=1
3     $0 E 1          +n$        s3 → 移进 +，进入状态3
4     $0 E 1 + 3      n$         s4 → 移进 n，进入状态4
5     $0 E 1 + 3 n 4  $         r1 → 用 E→E+n 归约
                                 弹出 |E+n|=3 对 = 6个
      $0              $          t=0, Goto[0,E]=1
6     $0 E 1          $          acc → 接受！
```

---

## 二、用 SLR(1) 分析——分析 `n + n + n`

### SLR(1) 分析表

```
     n    +    $    E
0    s2            1
1         s3   acc
2         r2   r2
3    s4
4         r1   r1
```

对比 LR(0)：状态2 在 n 列不再填 r2（因为 n ∉ FOLLOW(E)），状态1 只在 $ 上 acc。

### 分析过程

```
步骤  栈                   输入       动作
1     $0                  n+n+n$     s2
2     $0 n 2              +n+n$      r2 (E→n), Goto[0,E]=1
3     $0 E 1              +n+n$      s3
4     $0 E 1 + 3          n+n$       s4
5     $0 E 1 + 3 n 4      +n$       r1 (E→E+n), Goto[0,E]=1
6     $0 E 1              +n$        s3
7     $0 E 1 + 3          n$         s4
8     $0 E 1 + 3 n 4      $         r1 (E→E+n), Goto[0,E]=1
9     $0 E 1              $          acc
```

### 关键观察

- 第2步归约时输入是 `+`（FOLLOW(E) 包含 +，所以可以归约）
- 第5步归约时输入也是 `+`，同理
- SLR(1) 用 FOLLOW 精确判断归约时机

## 三、用 LR(1) 分析——分析 `n + n`

### 构造 LR(1) DFA

```
(0) E' → E
(1) E  → E + n
(2) E  → n
```

```
I₀ = Closure({[E'→·E, $]})
   = { [E'→·E, $],  [E→·E+n, $],  [E→·n, $] }

Goto(I₀, E) = { [E'→E·, $],  [E→E·+n, $] } = I₁
Goto(I₀, n) = { [E→n·, $] } = I₂

Goto(I₁, +) = Closure({[E→E+·n, $]})
            = { [E→E+·n, $] } = I₃

Goto(I₃, n) = { [E→E+n·, $] } = I₄
```

这个文法简单，LR(1) DFA 和 LR(0) DFA 完全一样（因为前瞻符没产生分化）。

### LR(1) 分析表

```
     n    +    $    E
0    s2            1
1         s3   acc
2              r2              ← 只在 $ 列 r2！
3    s4
4              r1              ← 只在 $ 列 r1！
```

**对比 SLR(1)**：状态2 在 `+` 列 SLR(1) 填了 r2（因为 +∈FOLLOW(E)），而 LR(1) 的前瞻符是 $，不在 + 列填 r2。

### 分析 `n + n`

```
步骤  栈              输入    动作
1     $0             n+n$    s2
2     $0 n 2         +n$     ERROR？不——
                             
这里输入 +，Action[2, +]  LR(1):空  SLR(1):r2
```

**注意**：LR(1) 表在状态2对 `+` 为空！这意味着 `n+n` 在 LR(1) 中会在第二步报错。

实际上 `n+n` 合法——说明这个 LR(1) DFA 构造有误。问题在于 I₀：
```
[E→·E+n, $] → 点后是 E，β=+n, a=$ → FIRST(+n$)={+} 
→ [E→·n, +] 也应该在 I₀ 中！
```

**修正后的 I₀**：
```
I₀ = { [E'→·E, $],  [E→·E+n, $],  [E→·n, $],  [E→·n, +] }
```

Goto(I₀, n) 产生：
```
I₂ = { [E→n·, $],  [E→n·, +] }
```

修正后的 LR(1) 表：

```
     n    +    $    E
0    s2            1
1         s3   acc
2         r2   r2              ← + 列有 r2 了！
3    s4
4         r1   r1
```

和 SLR(1) 一样——这个文法恰好所有四种方法表相同。

## 四、用 LALR(1) 分析

LALR(1) 的分析过程和 LR(1) **完全一样**，区别只是分析表来自合并同心集后的 DFA。

对这个简单文法，LALR(1) 分析表 = LR(1) 分析表 = SLR(1) 分析表（没有同心集可合并）。

---

## 五、分析过程对比——四种方法用同一个算法

| 步骤 | 操作 | 栈变化 | ip变化 | 查什么表 |
|------|------|--------|--------|---------|
| 移进 | 发现 Action=sⱼ | push(a); push(j) | ip++ | Action |
| 归约 | 发现 Action=rⱼ | 弹 2×|β| 个; push(A); push(Goto[t][A]) | **不动** | Action + Goto |
| 接受 | 发现 acc | — | — | Action |

### 栈的规律（四种方法通用）

```
栈内容：$  0  符号1  状态1  符号2  状态2  ...  符号k  状态k
        └─底─┘  └─ 文法符号 ─┘  └─ 状态 ─┘
```

- 文法符号和状态**交替**存放
- 移进：压入符号 + 新状态（栈增长 2）
- 归约：弹出 |β| 对（2|β| 个），压入 A + 新状态（栈净减少 2|β| - 2）
- ip **只在移进时前进**，归约时不动

## 六、一个更复杂的例子：括号文法

```
(0) S' → S
(1) S  → (S)S
(2) S  → ε
```

FOLLOW(S) = {$, )}
FOLLOW(S') = {$}

### LR(0) DFA

```
I₀: S'→·S,  S→·(S)S,  S→·       ← S→· 是归约项目！
I₁: S'→S·
I₂: S→(·S)S,  S→·(S)S,  S→·
I₃: S→(S·)S
I₄: S→(S)·S,  S→·(S)S,  S→·
I₅: S→(S)S·
```

### 分析表对比

**LR(0) 表**：I₀/I₂/I₄ 都有 `S→·` 归约项目，要对所有符号归约，同时又有移进，大量冲突 → **不是 LR(0)**。

**SLR(1) 表**：`S→·` 只在 FOLLOW(S) = {$, )} 时归约。移进符号是 `(`。{$,)} ∩ {(} = ∅ → 无冲突 → **是 SLR(1)**。

| 状态 | ( | ) | $ | S |
|------|---|---|---|---|
| 0 | s2 | r2 | r2 | 1 |
| 1 | | | acc | |
| 2 | s2 | r2 | r2 | 3 |
| 3 | | s4 | | |
| 4 | s2 | r2 | r2 | 5 |
| 5 | | r1 | r1 | |

### 用 SLR(1) 分析 `( )`

```
步骤  栈               输入     动作
1     $0              ( ) $    s2
2     $0 ( 2          ) $      r2 (S→ε): 弹0个, Goto[2,S]=3
3     $0 ( 2 S 3      ) $      s4
4     $0 ( 2 S 3 ) 4  $       r2 (S→ε): 弹0个, Goto[4,S]=5
5     $0 ( 2 S 3 ) 4 S 5 $    r1 (S→(S)S): 弹3对=6个, Goto[0,S]=1
6     $0 S 1          $       acc
```

### 关键观察

- 步骤2和4：`S→ε` 归约时**弹出0个符号**（|β|=0），栈反而增长了（压入 S + Goto）
- 步骤5：一次归约吃掉 `( S ) S` 三个符号 → 弹出6个，整个括号结构消失
- 看到 `S→ε` 归约时，输入符号必须是 `)` 或 `$`（FOLLOW(S)），不能是 `(`

## 七、分析技巧总结

### 归约时的三个动作

```
1. 弹：弹出 2 × |β| 个（符号+状态交替）
2. 查：查新栈顶在 Goto 表中的值
3. 压：压入 A + Goto[t][A]
```

### 空产生式归约的特殊性

```
A → ε 归约时：
  |β| = 0
  弹出 0 个
  压入 A + Goto[t][A]
  栈高度反而 +2！
```

### 符号表中的作用

```
FOLLOW 在 SLR(1) 中的作用：
  — 决定归约时机（输入符号是否在 FOLLOW 中）

前瞻符在 LR(1)/LALR(1) 中的作用：
  — 精确控制归约，比 FOLLOW 更细粒度
```

## 八、四种方法分析能力速记

| 方法 | 能否分析 `( )` 括号文法？ | 能否分析 C 语言 if-else？ |
|------|------------------------|-------------------------|
| LR(0) | 不能（S→ε 和 S→(S)S 冲突） | 不能 |
| SLR(1) | **能**（FOLLOW 解决） | 不能（else 冲突） |
| LALR(1) | **能** | **能** |
| LR(1) | **能** | **能** |
