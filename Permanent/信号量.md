# 信号量

## 什么是信号量

**信号量（Semaphore）** 是一种用于[[进程]]/[[线程]]同步与互斥的经典机制，由 Dijkstra 在 1965 年提出。它是一个整型变量，配合两个原子操作 **P（wait）** 和 **V（signal）** （[[PV操作]]）来实现对共享资源的受控访问。

## 核心概念

### 信号量类型

| 类型 | 描述 | 取值 |
|------|------|------|
| **二进制信号量** | 取值 0 或 1，类似互斥锁 | 0 / 1 |
| **计数信号量** | 取值 ≥ 0，表示可用资源数量 | 0, 1, 2, ... |

### 原子操作

#### P 操作（wait / down / acquire）
```
P(S):
    while S <= 0:   // 如果资源不足，阻塞等待
        block
    S = S - 1       // 占用一个资源
```

#### V 操作（signal / up / release）
```
V(S):
    S = S + 1       // 释放一个资源
    if 有进程在等待:
        wakeup       // 唤醒一个阻塞进程
```

> 在实际实现中，P 和 V 必须是**原子操作**，不可被中断。

## 经典同步问题

### 1. [[生产者-消费者问题]]（Bounded Buffer）

```c
Semaphore mutex = 1;      // 缓冲池互斥
Semaphore empty = N;      // 空缓冲区数量
Semaphore full = 0;       // 满缓冲区数量

void producer() {
    while (true) {
        produce(&item);
        P(&empty);         // 请求空缓冲区
        P(&mutex);         // 进入临界区
        put(item);         // 放入缓冲区
        V(&mutex);         // 离开临界区
        V(&full);          // 增加满缓冲区计数
    }
}

void consumer() {
    while (true) {
        P(&full);          // 请求满缓冲区
        P(&mutex);         // 进入临界区
        item = get();      // 从缓冲区取出
        V(&mutex);         // 离开临界区
        V(&empty);         // 增加空缓冲区计数
        consume(&item);
    }
}
```

> ⚠ **P 操作的顺序很重要**：一般先做资源信号量的 P，再做互斥信号量的 P，否则可能导致死锁。

### 2. [[读者-写者问题]]

```c
Semaphore rw_mutex = 1;    // 写者互斥
Semaphore mutex = 1;       // 保护 read_count
int read_count = 0;

void writer() {
    P(&rw_mutex);          // 请求写权限
    write();
    V(&rw_mutex);          // 释放写权限
}

void reader() {
    P(&mutex);
    read_count++;
    if (read_count == 1)
        P(&rw_mutex);      // 第一个读者阻止写者
    V(&mutex);

    read();

    P(&mutex);
    read_count--;
    if (read_count == 0)
        V(&rw_mutex);      // 最后一个读者释放写权限
    V(&mutex);
}
```

### 3. 哲学家就餐问题

```c
#define N 5
Semaphore chopstick[N] = {1};

void philosopher(int i) {
    while (true) {
        think();
        P(&chopstick[i]);           // 拿左筷子
        P(&chopstick[(i+1) % N]);   // 拿右筷子
        eat();
        V(&chopstick[i]);           // 放左筷子
        V(&chopstick[(i+1) % N]);   // 放右筷子
    }
}
```

> ⚠ 上述简单实现可能导致**死锁**（所有哲学家同时拿起左筷子）。解决方案包括：
> - 限制最多 N-1 位哲学家同时就餐
> - 奇数号先拿左再拿右，偶数号先拿右再拿左
> - 使用 `trywait`（非阻塞 P 操作）

## 信号量 vs 互斥锁

| 特性 | 信号量 | 互斥锁 |
|------|--------|--------|
| 用途 | 同步 + 互斥 | 互斥 |
| 所有权 | 无 | 有（谁加锁谁解锁） |
| 值域 | 任意非负整数 | 0 或 1 |
| 操作 | P / V | lock / unlock |
| 线程安全 | 需自行确保 | 通常内置 |

## 实现原理

信号量的底层通常依赖**操作系统内核**的支持：

1. **整型计数器** — 记录可用资源数量
2. **等待队列** — 记录因资源不足而阻塞的进程/线程
3. **原子操作** — 通过关中断、Test-and-Set 或 CAS 指令保证 P/V 的原子性

### 用户态 vs 内核态

```
用户态 P(S):
    if (S > 0)
        S-- (原子操作)
    else
        系统调用进入内核 → 阻塞当前线程

内核态 V(S):
    S++
    if (等待队列非空)
        唤醒队列头部线程
```

## 优缺点

### 优点
- 机制简单，适用范围广
- 既可以用于互斥，也可以用于同步
- 可解决多种经典并发问题

### 缺点
- **低级抽象**：P/V 分散在代码中，容易出错
- **易产生死锁**：P 操作顺序不当可能导致永久阻塞
- **无结构化**：缺少 RAII 等自动管理机制，忘记 V 操作会造成资源泄漏
- **调试困难**：并发问题难以复现和追踪
