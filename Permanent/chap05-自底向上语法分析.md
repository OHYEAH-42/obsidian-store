# 第五章：自底向上语法分析 — 深入讲解

## 1. 为什么需要自底向上分析？

### 1.1 自顶向下的局限
- LL(1) 要求文法无左递归、无左公因子
- 需要提取左公因子，引入大量非终结符
- **很多自然写法（如表达式左递归描述左结合）在 LL(1) 中必须改写**

### 1.2 自底向上的优势
- 可以处理**左递归**文法（天然适合表达式）
- 比 LL(1) 表达能力更强
- 实际编译器（GCC, Rustc）几乎都用 LR 系列算法

---

## 2. 移进-归约分析的基本原理

### 2.1 一个直观例子

文法：`S → cAd`, `A → ab | a`

输入：`cabd`

```
步骤    栈          剩余输入      动作
1       $           c a b d $    移进 c
2       $ c         a b d $      移进 a
3       $ c a       b d $        移进 b  ？还是归约 A→a ？

这里就是冲突点！a 既可以看作 A→a 的句柄，也可以等 b 来匹配 A→ab
```

**句柄 (Handle)**：当前句型中与某个产生式右部匹配、且归约后能到达开始符号的子串。

**关键**：何时该移进、何时该归约，就是 LR 分析的核心问题。

### 2.2 第二个例子

文法：`S → gAhBkC`, `A → ab`, `B → cd`, `C → ef`

输入：`gabhcdkef`

```
栈           输入          动作
$            gabhcdkef$   移进 g
$ g          abhcdkef$    移进 a
$ g a        bhcdkef$     移进 b
$ g a b      hcdkef$      归约 A→ab
$ g A        hcdkef$      ...
```

逐符号读入，找到句柄就归约。

## 3. LR(0) 分析（基础）

### 3.1 LR(0) 项目

在产生式右部中标记一个点 `.`，表示"已经读到了这里"。

```
产生式 E → E + n 的项目：
E → ·E + n    即将识别 E
E → E· + n    刚识别了 E，期望 +
E → E +· n    识别了 E+，期望 n
E → E + n·    全部识别完成，可以归约！
```

### 3.2 拓广文法

添加 `E' → E` 作为新的开始产生式，接受状态唯一。

```
原文法：E → E + n | n
拓广：  (0) E' → E
       (1) E → E + n
       (2) E → n
```

### 3.3 LR(0) DFA 的完整构造

**算法：Closure(I)**

```
Closure(I)：
  将 I 中所有项目加入结果
  while (结果中有变化)
    for (结果中的每个项目 A → α·Bβ)
      for (每个产生式 B → γ)
        将 B → ·γ 加入结果
```

**算法：Goto(I, X)**

```
Goto(I, X)：
  J = ∅
  for (I 中的每个项目 A → α·Xβ)
    将 A → αX·β 加入 J
  return Closure(J)
```

**示例：G[E']: E'→E, E→E+n | n**

```
I₀ = Closure({E'→·E})
   = {E'→·E, E→·E+n, E→·n}
   （加上 E→·E+n 和 E→·n 是因为"·"后面是 E）

Goto(I₀, E) = Closure({E'→E·, E→E·+n})
             = {E'→E·, E→E·+n} = I₁

Goto(I₀, n) = Closure({E→n·})
             = {E→n·} = I₂

Goto(I₁, +) = Closure({E→E+·n})
             = {E→E+·n} = I₃

Goto(I₃, n) = Closure({E→E+n·})
             = {E→E+n·} = I₄
```

**DFA 图**：
```
     E           +           n
→(I₀)──→(I₁)──→(I₃)──→(I₄)
   │ n
   └──→(I₂)
```

### 3.4 从 DFA 构造 LR(0) 分析表

**Action 表**的填写规则：
- 若 `A→α·aβ` 在状态 Iᵢ 中，且 Goto(Iᵢ, a) = Iⱼ → Action[i, a] = sⱼ（移进）
- 若 `A→α·` 在状态 Iᵢ 中（A≠S'）→ Action[i, 所有 a] = rⱼ（用第 j 条产生式归约）
- 若 `S'→S·` 在状态 Iᵢ 中 → Action[i, $] = acc（接受）

**Goto 表**的填写规则：
- 若 Goto(Iᵢ, A) = Iⱼ → Goto[i, A] = j

### 3.5 LR(0) 分析 n+n+n

```
状态    栈           输入          动作
0       $0           n+n+n$        s2 (移进到状态2)
2       $0 n 2       +n+n$         r2 (用 E→n 归约)
        $0            +n+n$         归约后弹出 |n|=1 个状态
        从状态0看 Goto(0,E)=1 → 压入 E,1
1       $0 E 1        +n+n$        s3 (移进 +)
3       $0 E 1 + 3    n+n$         s4 (移进 n)
4       $0 E 1 + 3 n 4 +n$         r1 (用 E→E+n 归约)
        $0            +n$           弹出 3 个状态
        从状态0看 Goto(0,E)=1
1       $0 E 1        +n$          s3
3       $0 E 1 + 3    n$           s4
4       $0 E 1 + 3 n 4 $           r1 (用 E→E+n 归约)
        $0            $            弹出 3 个状态
1       $0 E 1        $            acc!
```

## 4. SLR(1) 分析

### 4.1 为什么需要 SLR(1)？

LR(0) 的问题：**任何归约项目在任何输入符号下都归约**，导致大量冲突。

```
状态 I₁ = {E'→E·, E→E·+n}
LR(0) 规则：E'→E· 归约（对所有输入，包括 +）
           E→E·+n 移进（输入为 +）
→ 当输入为 + 时：移进-归约冲突！
```

### 4.2 SLR(1) 的改进

**只在 FOLLOW(A) 包含的输入符号上执行归约 A→α**。

```
状态 I₁：
  E'→E·的 FOLLOW(E')={$} → 只有输入 $ 时归约
  E→E·+n → 输入 + 时移进
→ 不再冲突！$ 时归约，+ 时移进
```

### 4.3 SLR(1) 冲突的两类判定

**移进-归约冲突**：同一状态中同时有 `A→α·aβ` 和 `B→γ·`，且 `a ∈ FOLLOW(B)`

**归约-归约冲突**：同一状态中有 `A→α·` 和 `B→β·`，且 `FOLLOW(A) ∩ FOLLOW(B) ≠ ∅`

若均不出现，则文法是 SLR(1) 的。

### 4.4 SLR(1) 分析表构建规则

1. `A→α·aβ ∈ Iᵢ`，Goto(Iᵢ, a) = Iⱼ → **Action[i, a] = sⱼ**
2. `A→α· ∈ Iᵢ`，a ∈ FOLLOW(A) → **Action[i, a] = rⱼ**（关键改进！）
3. `S'→S· ∈ Iᵢ` → **Action[i, $] = acc**
4. Goto(Iᵢ, A) = Iⱼ → **Goto[i, A] = j**

### 4.5 完整示例：E→E+n|n 的 SLR(1)

```
DFA：
I₀ = {E'→·E, E→·E+n, E→·n}
I₁ = {E'→E·, E→E·+n}    FOLLOW(E')={$}
I₂ = {E→n·}               FOLLOW(E)={$,+}
I₃ = {E→E+·n}
I₄ = {E→E+n·}             FOLLOW(E)={$,+}

分析表：
      n    +    $    E
0     s2            1
1          s3   acc
2     r2   r2        (r2: 输入为+或$时用E→n归约)
3     s4
4     r1   r1        (r1: 输入为+或$时用E→E+n归约)
```

## 5. SLR(1) 经典例题

### 5.1 例一：括号文法

```
S' → S
S → (S)S | ε
```

FOLLOW(S) = { $, ) }

**I₀ = {S'→·S, S→·(S)S, S→·}**
- S→· 是归约项目，ε ∈ FIRST(ε) → FOLLOW(S) = {$,)}
- S→·(S)S 有移进 (
- 冲突？( 在 FOLLOW(S) 中！→ **( 上同时有移进和归约  → 不是 SLR(1)**？
  
但实际上这是 SLR(1) 的，因为：S→· 归约时输入必须是 FOLLOW(S) 中的符号即 `)` 或 `$`，而 S→·(S)S 要求移进 `(`。所以 ( 和 ) 不会同时触发。

等等，仔细看：S→· 的 FOLLOW(S) = {$,)} 包含 `)`，但不包含 `(`。S→·(S)S 的移进是 `(`。这两个集合不相交！所以**没有冲突**。

### 5.2 例二：if-else 的 SLR(1) 分析

```
S' → S
S → I | other
I → if S | if S else S
```
简化为：
```
(0) S' → S
(1) S → I
(2) S → other
(3) I → if S
(4) I → if S else S
```

FOLLOW(I) = {$, else}（I 后面跟 $ 或 else）

在某个状态中，同时有 `I→if S·` 和 `I→if S·else S`：
- 归约项目 I→if S· 对 FOLLOW(I) = {$, else} 归约
- 移进项目 I→if S·else S 对 else 移进
- → **在 else 上冲突！**

**解决**：规定 else 移进（就近匹配），消除移进-归约冲突。

### 5.3 例三：赋值语句文法

```
S' → S
S → id | V := E
V → id
E → V | n
```

DFA 构造后：
- FOLLOW(S) = {$}
- FOLLOW(V) = {:=, $}
- FOLLOW(E) = {$}

状态 X = {V→id·}：
- FOLLOW(V) = {:=, $}
- 输入为 `:=` 时归约 ✓
- 输入为 `$` 时归约 ✓
- 没有冲突！

实验四要求判断一个输入文法是否是 SLR(1) 的。

## 6. LR(1) 分析

### 6.1 SLR(1) 的问题

SLR(1) 用**全局**的 FOLLOW 集来决定归约，但特定上下文中，A 后面实际能出现的符号可能比 FOLLOW(A) 小。

**LR(1) 为每个项目附加一个前瞻符 (lookahead)**，精确描述"在这个状态下，归约 A→α 只能在输入为 a 时进行"。

### 6.2 LR(1) 项目

形式：`[A → α·β, a]`
- A→α·β 是核心（与 LR(0) 相同）
- a 是前瞻符：归约时只有下一个输入是 a 时才执行

### 6.3 LR(1) 闭包算法

```
Closure(I)：
  for (I 中的每个项目 [A→α·Bβ, a])
    for (每个产生式 B→γ)
      for (每个 b ∈ FIRST(βa))
        将 [B→·γ, b] 加入 I
```

**关键**：新加入的项目 `B→·γ` 的前瞻符是 `FIRST(βa)`，而不是简单地继承 a。

### 6.4 完整示例：A → (A) | a

```
(0) A' → A
(1) A → (A)
(2) A → a
```

**I₀ = Closure({[A'→·A, $]})**
```
[A'→·A, $]  →  B=A, β=ε, a=$
             →  b = FIRST(ε$) = {$}
加入 [A→·(A), $] 和 [A→·a, $]
```
I₀ = {[A'→·A, $], [A→·(A), $], [A→·a, $]}

**Goto(I₀, ()**
```
从 [A→·(A), $] 得 [A→(·A), $]
Closure: β=), a=$ → FIRST()$)={)}
加入 [A→·(A), )] 和 [A→·a, )]
```
I₁ = {[A→(·A), $], [A→·(A), )], [A→·a, )]}

**注意**：`[A→·(A), )]` 的前瞻是 `)`，而 `[A→·(A), $]` 的前瞻是 `$`。这两个是**不同的 LR(1) 项目**！

**完整的 LR(1) DFA** 有更多状态（比 LR(0) 多），因为同一个"核心"附带不同的前瞻符。

### 6.5 用 LR(1) 分析 ((a))

LR(1) DFA 的状态数远多于 SLR(1)，使得每一步的归约决策更加精确。((a)) 的分析不会出现 SLR(1) 的冲突。

## 7. LALR(1) 分析

### 7.1 核心思想

LR(1) 状态太多（可达数千），**LALR(1) = 合并 LR(1) DFA 中核心相同、仅前瞻符不同的状态**。

### 7.2 合并算法

```
1. 构造 LR(1) DFA
2. 找出所有核心（去掉前瞻符的部分）相同的状态
3. 合并它们：前瞻符取并集
4. 检查合并后是否引入新的归约-归约冲突
```

**重要特性**：
- 合并后**不会引入新的移进-归约冲突**
- 可能引入新的**归约-归约冲突**（概率很小）
- 状态数与 SLR(1) 相同（即与 LR(0) DFA 相同）

### 7.3 LALR(1) 的实用价值

- **Yacc/Bison** 默认使用 LALR(1)
- 分析能力强（接近 LR(1)）
- 分析表小（与 SLR(1) 同大）
- 你的**实验四就是实现 LALR(1) 语法分析生成器**！

## 8. 实验四：LALR(1) 语法分析生成器

### 8.1 必做功能
1. **文法编辑器**：载入、保存文法文件
2. **FIRST/FOLLOW 计算**：计算并显示各非终结符的 FIRST 和 FOLLOW 集
3. **LR(0) DFA 图**：显示 LR(0) 项目集 DFA
4. **SLR(1) 判定**：判断并显示是否为 SLR(1)，若冲突说明原因
5. **LR(1) DFA 图**：显示 LR(1) 项目集 DFA
6. **LALR(1) DFA 图**：显示合并后的 LALR(1) DFA

### 8.2 核心数据结构

```cpp
// LR(0) 项目
struct LR0Item {
    int ruleNo;      // 产生式编号
    int dotPos;      // 点的位置 (0 = 最左, len = 最右)
};

// LR(1) 项目
struct LR1Item {
    int ruleNo;
    int dotPos;
    set<int> lookaheads;  // 前瞻符集
};

// DFA 状态
struct State {
    vector<LR1Item> items;
    map<int, int> transitions;  // 字符 → 目标状态
};
```

### 8.3 测试文法（必测）

```
exp   → exp addop term | term
addop → + | -
term  → term mulop factor | factor
mulop → * | /
factor → ( exp ) | n
```

## 9. LR 分析器家族总结

| 方法 | 能力 | DFA状态数 | 构造难度 | 实际工具 |
|------|------|----------|---------|---------|
| LR(0) | 弱 | 少 | 简单 | 无 |
| SLR(1) | 中 | 同LR(0) | 较简单 | 教学为主 |
| LR(1) | 最强 | 极多 | 复杂 | 极少直接用 |
| **LALR(1)** | **接近LR(1)** | **同LR(0)** | **适中** | **Yacc/Bison** |

**能力排序**：LR(0) < SLR(1) < LALR(1) < LR(1)
