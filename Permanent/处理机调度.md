**处理机调度**（Processor Scheduling / CPU Scheduling）是[[操作系统]]的核心功能之一，它决定[[进程]]或[[线程]]何时、由谁获得 CPU 的使用权。调度的质量直接影响系统的性能指标——吞吐量、响应时间和资源利用率。

# 调度的三个层次

| 层次 | 别名 | 调度对象 | 发生频率 | 功能 |
|:---|:---|:---|:---|:---|
| **高级调度** | 作业调度（Long-Term） | 作业（从外存→内存） | 低 | 决定哪些作业被允许进入内存创建进程 |
| **中级调度** | 交换调度（Medium-Term） | 进程（内存↔外存） | 中等 | 将暂不运行的进程换出到外存，缓解内存压力 |
| **低级调度** | 进程/线程调度（Short-Term） | 进程/线程（就绪→运行） | 非常高 | 从就绪队列中选择一个进程分配 CPU |

现代操作系统主要关注**低级调度**（即通常所说的"处理机调度"）。

# 调度时机

发生调度的典型情况（以 xv6 等教学 OS 为例）：
1. 进程主动放弃 CPU（如等待 I/O、调用 `exit`）
2. 时钟[[中断]]——时间片耗尽
3. 高优先级进程进入就绪队列（抢占式调度）

# 评价指标

| 指标 | 定义 | 关注方 |
|:---|:---|:---|
| **CPU 利用率** | CPU 处于忙碌状态的时间占比 | 系统管理员 |
| **吞吐量**（Throughput） | 单位时间内完成的进程数量 | 系统管理员 |
| **周转时间**（Turnaround Time） | 从进程提交到完成的总时间 = 等待 + 执行 + I/O | 用户 |
| **等待时间**（Waiting Time） | 进程在就绪队列中等待的总时间（不包括 I/O 等待） | 用户 |
| **响应时间**（Response Time） | 从提交请求到产生首次响应的时间 | 交互式用户 |

# 典型调度算法

## 1. 先来先服务（FCFS）
- 非抢占式，按到达顺序调度
- 优点：公平、实现简单
- 缺点：平均等待时间长，**护航效应**（convoy effect）——短进程等长进程

## 2. 最短作业优先（SJF / SRTF）
| 变体 | 全称 | 抢占性 |
|:---|:---|:---|
| **SJF** | Shortest Job First——最短作业优先 | 非抢占 |
| **SRTF** | Shortest Remaining Time First——最短剩余时间优先 | 抢占 |
- 优点：**理论上平均等待时间最小**
- 缺点：难以预知进程的执行时间，可能导致长进程**饥饿**（starvation）

## 3. 优先级调度（Priority Scheduling）
- 每个进程关联一个优先级，高优先级先运行
- 抢占式/非抢占式两种变体
- 问题：低优先级进程可能无限等待（饥饿）→ 解决方案：**老化**（Aging），随时间逐步提升低优先级进程的优先级

## 4. 时间片轮转（Round-Robin, RR）
- 每个进程最多运行一个时间片（time slice / quantum）
- **抢占式**，FCFS + 时间片限制
- 优点：响应时间短，适合分时系统
- 关键参数：时间片大小
  - 太小 → 上下文切换开销过大
  - 太大 → 退化为 FCFS，响应变慢

## 5. 多级队列调度（Multilevel Queue）
- 就绪队列分为多个独立队列，各队列可拥有不同的调度算法
- 例如：前台（交互式）用 RR，后台（批处理）用 FCFS
- 队列间有优先级，可能发生**饥饿**

## 6. 多级反馈队列调度（Multilevel Feedback Queue, MLFQ）
- 进程可在不同优先级队列间**动态迁移**
- 高优先级队列时间片短，低优先级队列时间片长
- 特点：**兼顾响应时间和吞吐量**，自动区分交互型与计算密集型进程
- 经典实现：BSD UNIX、xv6 的调度器

# 调度的分类

- **非抢占式调度**（Non-preemptive / Cooperative）：进程自愿让出 CPU
- **抢占式调度**（Preemptive）：操作系统有权强行剥夺进程的 CPU 使用权

现代通用操作系统（Linux、Windows、macOS）均使用**抢占式多级反馈队列调度**。
