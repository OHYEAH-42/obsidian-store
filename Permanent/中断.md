**中断**（Interrupt）是[[操作系统]]中 CPU 对系统内外部发生的**异步事件**的一种响应机制。中断是现代操作系统实现[[并发]]、[[多道批处理系统|多道程序设计]]和[[虚拟|虚拟化]]的核心硬件支撑。

# 中断的分类

中断按来源分为两大类：

## 内中断（Internal Interrupt / Exception）

来自 CPU 内部，由指令执行过程中发生的异常情况触发：

| 类型 | 别称 | 触发原因 | 是否可恢复 |
|:---|:---|:---|:---|
| **陷阱**（Trap） | 软件中断 | 主动触发（如 `int`、`syscall` 指令） | 是 |
| **故障**（Fault） | 可恢复异常 | 缺页、除零、段错误 | 通常可恢复 |
| **终止**（Abort） | 不可恢复异常 | 硬件错误、系统崩溃 | 否，进程终止 |

## 外中断（External Interrupt / Hardware Interrupt）

来自 CPU 外部，由硬件设备发出的电信号触发：

| 类型 | 触发源 | 说明 |
|:---|:---|:---|
| **I/O 中断** | 磁盘、键盘、网卡等 | 设备完成任务后通知 CPU |
| **时钟中断**（Timer Interrupt） | 可编程间隔定时器（PIT/APIC） | 用于时间片轮转调度、系统时间维护 |
| **硬件故障中断** | 电源故障、内存校验错 | 紧急处理 |

# 中断处理过程

1. **中断检测**：CPU 在执行每条指令的末尾检测是否有中断信号
2. **中断响应**：保存当前[[上下文]]（[[程序计数器]]、寄存器等），关中断
3. **中断识别**：根据中断号从中断向量表（Interrupt Vector Table / IDT）查到对应的[[handler|中断处理程序]]入口
4. **中断处理**：执行中断处理程序（[[handler]]），完成具体操作
5. **中断返回**：开中断，恢复上下文，返回断点继续执行

# 中断与系统调用的关系

系统调用（System Call）本质上是**一种特殊的软件中断**（陷阱）：

- 用户[[程序]]通过 `int` 或 `syscall` 指令主动触发陷阱
- CPU 切换到内核态，跳转到系统调用入口
- 处理完成后返回用户态

# 中断向量表（IDT）

- 存放中断号 → 中断处理程序入口地址的映射表
- 由[[操作系统]]在初始化阶段设置
- x86 架构使用中断描述符表（Interrupt Descriptor Table, IDT），支持 256 个中断向量

# 中断在 OS 中的意义

操作系统常被称为**中断驱动**（Interrupt-Driven）——没有中断，操作系统无法感知外部事件，也无法主动回收 CPU 控制权。中断是操作系统实现以下功能的基础：

- 设备 I/O 的异步通知
- CPU 虚拟化（时钟中断实现[[分时系统|分时]]）
- 系统调用（用户态→内核态的入口）
- 异常处理（保护系统免受程序错误影响）
