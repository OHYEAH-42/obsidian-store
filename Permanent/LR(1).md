# LR(1) 文法

LR(1) = **规范 LR**。**1** 表示向前看 **1** 个符号来决定动作。它对 SLR(1) 的改进是：不再用全局的 FOLLOW 集，而是为每个项目附上一个**精确的[[前瞻符]]**。一种[[语法分析]]中[[自底向上的语法分析]]的方法


## 为什么需要 LR(1)？

SLR(1) 的问题：FOLLOW(A) 是"所有可能跟在 A 后面的符号"的**并集**，但在某个特定状态下，A 后面实际能跟的符号只是 FOLLOW(A) 的**子集**。

```
FOLLOW(E) = {$, +, )}        ← 全局，涵盖所有可能

但在状态 Iₓ 中，E 后面可能只会出现 $，不会出现 +：
  SLR(1) 对 $, +, ) 都填归约 → 在 + 列上可能导致误归约或冲突
  LR(1)  只对 $ 填归约 → 精确！
```

LR(1) 的做法：**向前看符号不再是 FOLLOW(A)，而是"在当前状态下，这个产生式归约时实际能遇到的符号"**。

# 基本概念

## [[前瞻符]]

**[[LR(1)]] 前瞻符**（Lookahead）是 LR(1) 分析中附加在**[[项目]]**（Item）上的一个终结符，用于决定在哪些输入符号下可以进行归约，从而消除移进/归约冲突。

## LR(1) [[项目]]

形式：**`A → α·β, a`**

- `A → α·β`：核心（与 LR(0) 相同）
- `a`：**[[前瞻符]]（lookahead）**，表示归约时只有当**下一个输入符号 = a** 才执行

```
[A → α·, a]  ← 归约项目：只有输入为 a 时才归约
[A → α·, b]  ← 同一个核心，不同前瞻符 → 不同的 LR(1) 项目
```

只有r操作与[[LR(0)]]有区别
LR(0)中，我们会在相应状态的action的每一行填入产生式对应的次序n的r<sub>n</sub>
LR(1)中，我们只在当前项目的[[前瞻符]]的一列填r<sub>n</sub>
